# Bàn giao G1 — Core API

Ngày **23/11/2026**. Hoàn thành phạm vi G1 của kế hoạch: SQLite, import/export,
tra cứu, chuẩn hóa, đóng gói pip và unit test. Hướng dẫn tại [README G1](README.md).

| Hạng mục | Kết quả bàn giao |
|---|---|
| SQLite | Khóa TEXT, FK bật, index lookup/quan hệ, schema version 1; import nguyên transaction, rollback khi lỗi |
| Dữ liệu đầu vào | Profile synset nghiên cứu v1/v2 và fixture concept G0; v2 đã kiểm chứng trên dữ liệu thực |
| Import/export | Giữ nguyên byte mọi file, ID, nhãn, review, null, evidence và mapping gộp; kiểm tra checksum/count; từ chối ghi đè |
| Lookup | NFC/casefold/khoảng trắng, có dấu; alias và đa nghĩa; không chọn sense tự động |
| Quan hệ | Truy vấn hai chiều theo ID; các proposal chỉ có object_term giữ needs_review |
| Trạng thái | Research chọn rõ; approved có điều kiện review/evidence, export kiểm thêm khai báo quyền |
| Package | `emotionet-0.1.0.dev0-py3-none-any.whl`, Python ≥3.10; core không có dependency ngoài |
| Tương thích | Giữ các tên import matcher/features/head/dataset hiện có; dependency ML nạp khi cần |

## Kết quả chạy thực tế

Môi trường Windows, Python 3.11.6. Không sử dụng test phần mềm để chứng nhận độ
đúng cảm xúc hoặc quyền nguồn dữ liệu.

| Kiểm tra | Kết quả |
|---|---|
| `python -m unittest discover -s tests -v` | **69/69 đạt, 0 skip**, gồm 20 test core mới |
| Import v2 | 77 entry, 82 sense, 66 concept, 90 evidence, 29 relation |
| JSONL → SQLite → JSONL | Mọi file khớp byte; export nhập lại thành công, lookup giống nhau |
| Polysemy và Unicode | `thương`, `lo`, `tiếc`, `ghét` giữ nhiều sense; NFD/viết hoa/khoảng trắng khớp cùng entry |
| Nhãn đã chốt | `khó chịu` giữ annoyance; `yêu thương` giữ love/caring |
| Dữ liệu lỗi | Duplicate ID, FK/evidence thiếu, membership sai, cycle, JSON trùng key, checksum/count sai bị chặn; DB rollback |
| Bảo vệ trạng thái | Candidate/accepted không tự approved; alias chưa approved bị lọc; quyền hạn chế ở record không bị manifest ghi đè |
| Build offline | `pip wheel --no-index --no-deps --no-build-isolation --wheel-dir dist .` đạt |
| Cài wheel sạch | Cài vào `build/g1-venv`; không có NumPy/PyTorch; smoke import đúng từ `site-packages`, lookup/roundtrip đạt |
| Smoke GA–xLSTM | Forward/backward qua 4 mask đạt trên CUDA; dùng hidden state giả lập, không phải thử nghiệm encoder thật |

Lệnh smoke cho package đã cài:

```console
build/g1-venv/Scripts/python.exe scripts/smoke_test_core_api.py
```

Python hệ thống chưa cài package mới; smoke GA–xLSTM đã chạy với `src` thêm rõ
vào đường dẫn import, sử dụng NumPy/PyTorch hiện có:

```console
python -c "import runpy, sys; sys.path.insert(0, 'src'); runpy.run_path('scripts/smoke_test_ga_xlstm_integration.py', run_name='__main__')"
```

Đã tạo DB dùng ngay tại `data/local/emotionet-v2.sqlite`. SQLite, wheel và venv
là artifact sinh lại được, theo `.gitignore`; source JSONL vẫn là đầu vào được
theo dõi trong Git. Cấu hình chọn snapshot nghiên cứu chung không bị thay đổi.

## Giới hạn và việc tiếp theo

- G1 dùng snapshot bất biến, mỗi DB một phiên bản. Reviews/emotions JSONL phụ
  được lưu nguyên và kiểm tra cú pháp; chưa có công cụ biên soạn hoặc kiểm tra
  ngữ nghĩa riêng. Mapping ID cũ được bảo toàn, chưa tự resolve khi lookup ID.
- 29 relation nghiên cứu chưa thành đồ thị đã duyệt; cần xác định sense đích và
  bằng chứng quyết định quan hệ. Alias/sense lookup chưa phải WSD.
- G2 cần đạt ≥300 concept đã duyệt và có provenance. 66 synset hiện tại là số
  lượng vật lý của snapshot nghiên cứu, không đồng nghĩa 66 concept đã qua đầy
  đủ cổng approved của API.
- G3 cần gold set riêng và sửa các giới hạn matcher còn lại; G4 cần lớp cảm xúc
  có ngữ cảnh và tích hợp encoder xLSTM thật; CLI sản phẩm/benchmark/release ở G5.

Chính sách chia sẻ giữ nguyên quyết định G0; không thêm giấy phép tái sử dụng
hoặc đổi trạng thái nguồn thành được cấp phép mở.
